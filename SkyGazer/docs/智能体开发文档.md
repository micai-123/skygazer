# 天气系统智能问答Agent开发指南（基于RAG + LangChain）

## 开发提示词

### 主题
天气系统智能问答Agent开发指南（基于RAG + LangChain）

### 目标
构建一个能根据用户天气查询生成精准答案的智能体，集成至现有天气系统。

### 技术栈
RAG、LangChain、向量数据库（如Chroma）、大模型（如Qwen）、Embedding模型、前后端API。

### 协作分工

| 角色 | 职责 |
|------|------|
| **前端开发** | 设计用户交互界面，处理用户输入并调用后端API，展示答案及解析过程（可选）。 |
| **后端开发** | 搭建API接口，对接天气数据源，调用RAG流程，管理向量数据库，处理请求与响应。 |
| **大模型开发** | 构建RAG流程（文档解析、向量化、检索、生成），优化模型推理逻辑，确保答案准确性。 |

### 核心流程

1. 用户提问 → 前端发送请求至后端API。
2. 后端解析请求，调用RAG服务：文本分块 → 向量化存储 → 检索相关文档 → 模型生成答案。
3. 后端整合答案并返回给前端。

### 关键注意事项

- **数据预处理**：天气数据结构化、分块、向量化。
- **RAG服务配置**：Chroma数据库、Embedding模型（Qwen）、Retriever与Reranker参数。
- **模型生成逻辑**：结合检索上下文与大模型输出。
- **接口设计**：定义清晰API规范（请求/响应格式、错误处理）。
- **安全与性能**：数据权限、查询优化、缓存机制。

## 一、项目目标

开发一个基于RAG和LangChain的智能问答Agent，集成至天气系统，实现以下功能：

1. 根据用户自然语言查询（如"北京未来三天天气如何？"），返回准确、结构化的天气信息。
2. 支持多类型查询：实时天气、历史数据、预报、灾害预警等。
3. 答案可追溯，基于天气系统数据源生成，避免幻觉。

---

## 二、技术架构

### 1. 数据层

- **天气数据源**：对接现有系统API或数据库，获取实时/历史天气数据。
- **知识库构建**：将天气数据结构化（JSON/CSV），使用Text Splitter分块，通过Embedding模型（如Qwen）向量化，存储于Chroma向量数据库。

### 2. 模型层（RAG流程）

```
┌─────────────────────────────────────────────────────────────────┐
│                        RAG 流程架构                              │
├─────────────────────────────────────────────────────────────────┤
│  文本解析 → 向量化 → 检索 → 重排（可选） → 生成                    │
└─────────────────────────────────────────────────────────────────┘
```

| 步骤 | 说明 |
|------|------|
| **文本解析** | 加载天气文档，使用 `RecursiveCharacterTextSplitter` 分块（块大小：1024字符）。 |
| **向量化** | 调用 `initialize_embedding_model("qwen")` 生成向量，存入Chroma。 |
| **检索** | 用户提问 → Embedding向量化 → 在Chroma中检索Top-K相关文档块（参数：`retrieve_k=8`）。 |
| **重排（可选）** | 使用Reranker模型（如BAAI/bge-reranker-large）对检索结果二次排序，过滤低相关文档。 |
| **生成** | 结合检索上下文，调用LangChain LLM（如Qwen）生成最终答案，使用 `ConversationBufferWindowMemory` 管理对话历史。 |

### 3. 应用层

- **前端**：React/Vue等框架，发送用户查询至后端API，展示答案（含解析过程，如"基于XX数据生成"）。
- **后端**：Python/Django/Flask，提供API接口（如 `/query_weather`），处理请求并调用RAG服务，返回标准化响应（JSON格式）。

### 4. 安全与性能

- **数据权限**：仅允许授权用户访问天气数据API。
- **缓存**：对高频查询结果缓存，优化响应速度。
- **错误处理**：捕获模型超时、数据库异常等，返回友好提示。

#### 步骤1：模型配置


#### 步骤2：生成逻辑优化

- 确保生成答案包含数据源引用（如"根据北京市气象局2026-04-05数据..."）。

## 附录

### 术语表

| 术语 | 定义 |
|------|------|
| **RAG** | Retrieval-Augmented Generation，检索增强生成，结合检索和生成的技术。 |
| **Chroma** | 开源向量数据库，用于存储和检索向量化的文档。 |
| **Embedding** | 将文本转换为向量表示的过程。 |
| **Retriever** | 从向量数据库中检索相关文档的组件。 |
| **Reranker** | 对检索结果进行二次排序的模型，提高相关性。 |
| **LangChain** | 用于构建大模型应用的框架。 |
