4.2 RAG 检索增强生成管线

📥 入库管线 (Ingestion Pipeline)

1
文档读取
KnowledgeIngestionService.java 读取 classpath:knowledge/*.md 气象知识Markdown文件
2
分块策略
按段落聚合，每块最大800字符（CHUNK_MAX_CHARS=800），保证段落不被切断。从文件名提取 category 分类
3
向量化 (Embedding)
调用 Spring AI EmbeddingModel（阿里云 text-embedding-v2），生成固定维度向量
4
向量存储
RedisKnowledgeVectorStore.java 自研存储，Redis Hash结构：rag:doc:{id} 存储文档+向量JSON，rag:docs:all 索引集合
5
启动触发
@EventListener(ContextRefreshedEvent) 应用启动时若向量库为空自动入库；POST /agent/knowledge/refresh 手动重建

🔍 检索流程 (Retrieval Flow)

1
查询向量化
用户问题 → EmbeddingModel.embed(query) → 查询向量
2
暴力余弦相似度
遍历所有文档向量，计算 cosine similarity。配置：ragTopK=5, ragSimilarityThreshold=0.55
3
结果过滤排序
阈值过滤 → 按score降序 → 取TopK，失败时降级为空列表
4
拼入提示词
buildSystemPrompt() 将RAG检索知识片段拼接到系统身份提示词之后，作为上下文增强
⚠️ 当前状态：已切换至 DeepSeek API，该平台不提供 Embedding 接口。 application-dev.yml 中 vector-store-enabled: false 已关闭RAG检索。 会话记忆和工具调用功能不受影响，正常使用。

4.3 Tool Calling 工具调用机制

工具类文件位置@Tool 方法数据来源功能
WeatherTools tool/WeatherTools.java getCurrentWeather(location)
getRecentWeather(location, days) 		WeatherDataMapper (MySQL) 查询数据库最新实况天气 + 最近N天历史
LifeIndexTools tool/LifeIndexTools.java getLifeIndex(location)

工具调用循环关键代码：AiAgentServiceImpl.resolveWithTools() — 关闭模型内部工具执行，采用显式循环（最多5轮）自行驱动工具调用，避免Spring AI M6流式空参崩溃。每轮将工具调用过程以SSE step 事件实时推送给前端。

五、核心业务流程解析

5.1 天气数据请求 → 响应完整链路

①
前端发起请求
views/HomeView.vue → api/index.js weatherApi.getCurrent('北京')
GET /api/weather/current?location=北京 → Vite Proxy → localhost:8080
②
安全过滤器链
RateLimitFilter (IP限流120次/分钟) → JwtAuthenticationFilter (天气接口在白名单免鉴权) → Controller
③
Service层二级缓存策略
WeatherServiceImpl.getCurrentWeather():
Step 1: 查 Redis 缓存 → 命中则直接返回
Step 2: 未命中 → MetaWeatherClient.fetchForecast() 调用外部API
Step 3: 外部API成功 → 构建WeatherData → 入库MySQL + 写Redis(TTL)
Step 4: 外部API失败 → 回退查询MySQL历史数据
Step 5: 历史数据也不存在 → generateMockWeatherData() 生成模拟数据
④
小时预报生成算法
优先从 MetaWeather 日数据用正弦日变化曲线推演72小时逐小时数据；否则从历史数据或模拟生成
⑤
周预报生成算法
MetaWeather 真实多日数据 + 超出天数用 simulateDailyData() 补齐至7天
⑥
响应返回前端
ApiResponse 统一包装 {code:200, data:{...}, message:"success"} → 前端 Axios 响应拦截器自动解包 → Pinia Store 更新 → 视图响应式渲染

5.2 JWT 认证流程

1
注册/登录
POST /api/user/login → AuthService.authenticate() → BCrypt密码校验 → 生成JWT(24h有效期) → 返回 {token, user}
2
前端存储
stores/auth.js 将 token 存入 localStorage，Axios 拦截器自动为每个请求添加 Authorization: Bearer <token>
3
请求拦截
JwtAuthenticationFilter 从 Header 提取token → 解析用户名 → 加载UserDetails → 校验token签名和过期 → 设置SecurityContext
4
路由守卫
前端 router/index.js beforeEnter 检查 meta.requiresAuth → 未登录弹窗提示 → 暂存pendingAction回调

5.3 AI 智能体流式对话完整链路

1
用户输入
AIAssistantView.vue 输入"北京今天适合跑步吗？" + conversationId="demo-001"
2
POST /agent/query/stream
AgentController.streamQuery() → AiAgentServiceImpl.streamAsk()
3
加载会话记忆
Redis GET agent:memory:demo-001 → 反序列化 ChatMessageRecord 列表 → 窗口截断(最多20条)
4
RAG 检索（可选，当前关闭）
查询向量化 → RedisKnowledgeVectorStore.search() → 余弦相似度Top5 → 拼入系统提示词
5
构建系统提示词
"你是智观天象的AI助手天象智囊…" + RAG知识片段 + 使用工具获取实时天气
6
工具调用循环 (resolveWithTools)
第1轮: DeepSeek决定调用 getCurrentWeather("北京") → WeatherTools执行 → 返回天气数据
第2轮: DeepSeek决定调用 getLifeIndex("北京") → LifeIndexTools执行 → 返回生活指数
若无需更多工具，生成最终回答
7
流式输出 (SSE)
DeepSeek Stream Response → 每4字符分块 → data: {"type":"answer","content":"..."} → 实时推送前端 → 最后发送 data: [DONE]
8
保存新记忆
用户问题 + 助手回答 → JSON序列化 → SET agent:memory:demo-001 <json> → 覆盖写入Redis

5.4 天气图像识别流程

1
前端上传图片
用户选择天气图片 → multipart/form-data → POST /api/weather-image/predict
2
后端转发模型服务
WeatherImageController → WeatherImageService → WebClient POST → http://localhost:5000/predict

Python Flask 推理

返回结果

进入地图页面
