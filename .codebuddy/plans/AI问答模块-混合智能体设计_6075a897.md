## 用户需求

在现有「智观天象(SkyGazer)」Spring Boot 天气系统中，将当前仅拼接 system+user 文本的朴素对话（`AliyunAiService` + `AiController`/`AgentController`）升级为真正的 AI 问答智能体模块。

## 产品概述

基于已接入的阿里云百炼 Qwen 端点，构建天气领域混合智能体「天象智囊」：既能基于气象知识库做检索增强问答（RAG，带引用来源），又能自主调用工具获取实时天气/生活指数/气象预警数据，并保留多轮会话记忆。前端已对接 `/api/ai/**` 与 `/api/agent/**`，重构须保持接口契约兼容（尤其流式 SSE 返回 `Flux<String>`、`AgentResponse` 含 `references`/`sessionId`）。

## 核心特性

- **RAG 检索增强**：将气象文档知识库嵌入 Redis 向量库，回答附带可溯源引用（`references`/`referenceDetails`）。
- **工具调用 Agent**：模型自主决定调用天气查询、外部预报、生活指数、气象预警等工具获取实时数据。
- **多轮会话记忆**：按 `sessionId` 隔离的会话上下文（Redis 后端），支持连续追问。
- **混合编排**：`ChatClient` + `QuestionAnswerAdvisor` + `@Tool` 统一编排，兼容流式与非流式。
- **知识入库管线**：对接现有占位的 `/agent/knowledge/refresh`，实现可重复触发、带去重的知识库重建。
- **降级与权限**：Embedding/检索失败退化为纯模型回答；工具超时捕获并提示；保留 JWT/Security 校验。

## 三种候选方案对比（设计交付之一）

| 方案 | 形态 | 优点 | 缺点 | 适用度 |
| --- | --- | --- | --- | --- |
| A 纯 RAG | 仅向量检索+生成 | 实现简单、答案可溯源、无外部依赖 | 无法获取实时天气、易产生陈旧知识 | 中 |
| B 纯工具 Agent | 仅 @Tool 调实时接口 | 数据实时准确、无需向量库 | 无领域知识沉淀、无引用、token 消耗大 | 中 |
| C 混合形态（选定） | RAG + 工具 + 记忆 | 知识+实时互补、可溯源、可连续对话 | 复杂度最高、依赖 RediSearch、需入库管线 | 最优 |


## 技术栈选型

- **核心框架**：Spring AI（与 Spring Boot 3.2.5 兼容的 `1.0.0-M6` 或升 Boot 至 3.3.x 用 1.0 GA），通过 `spring-ai-bom` 管理版本。
- **模型接入**：`spring-ai-alibaba-starter-dashscope` 提供 `DashScopeChatModel` + `DashScopeEmbeddingModel`，原生对接 Qwen（`qwen-plus`）与 `text-embedding-v2/v3`；与现有 `ai.aliyun.*` 配置（OpenAI 兼容/DashScope 双端点）一致。（备选：`spring-ai-openai` 指向 `openaiCompatibleUrl` 亦可。）
- **向量存储**：`RedisVectorStore`（复用现有 Redis，**前提是其为 Redis Stack / 启用 RediSearch 模块**）+ `EmbeddingModel`。
- **会话记忆**：`MessageWindowChatMemory` + 自定义 `ChatMemoryRepository`（基于现有 `RedisTemplate` 的 Redis 后端，按 `sessionId` 隔离）。
- **编排**：`ChatClient`（流式 `Flux<ChatResponse>`）、`QuestionAnswerAdvisor`、`@Tool` 工具注解。
- **复用现有**：WebFlux（SSE 流式）、`RedisTemplate`、`WeatherDataMapper`(MyBatis)、`MetaWeatherClient`、`SecurityConfig`(JWT)、`AIModelException`。

## 实现策略（混合形态 C）

**高层思路**：用 `ChatClient` 作为统一入口，挂载 `QuestionAnswerAdvisor`（RAG 检索）与一组 `@Tool`（实时数据），并以 `ChatMemory` 注入历史消息；控制器将请求组装为 `Prompt` 并解析 `ChatResponse` 的元数据填充 `references`。

**关键技术决策**

1. **模型/Embedding 走 DashScope**：阿里云百炼同时提供对话与 embedding，避免引入第三方 Key；Embedding 维度固定（v2=1536/v3=1024），`RedisVectorStore` 的 `vectorDim` 须与之一致。
2. **Redis 复用但需 RediSearch**：`RedisVectorStore` 依赖 `FT.CREATE`/向量索引，普通 Redis 不支持；实现前须确认部署的是 Redis Stack。否则降级为 `SimpleVectorStore`（本地文件持久化）并在 notes 中明确。
3. **工具即现有能力封装**：`@Tool` 方法直接委托 `WeatherDataMapper`、`MetaWeatherClient` 及现有生活指数/预警 Service，零业务逻辑新增，符合 DRY。
4. **版本兼容**：Spring Boot 3.2.5 下采用 Spring AI `1.0.0-M6` 并添加 `spring-milestones` 仓库；若选 GA 则需升 Boot 至 3.3.x（单独评估，避免连带升级风险）。

**性能与可靠性**

- 向量检索 `topK=4~6`、`similarityThreshold` 过滤，避免噪声注入；入库用 `TokenTextSplitter` 分块（~500 token）。
- 记忆窗口限制（如 20 轮），防止 context 膨胀与 token 超支；SSE 使用 WebFlux 背压。
- 降级：Embedding/检索异常 → 跳过 Advisor 退化为纯模型；工具执行超时（统一 5s）→ 捕获返回友好提示，不阻断主流程。
- 并发：向量库写入仅在 `knowledge/refresh` 触发，使用去重标记（Redis key `rag:ingested:v{n}`）幂等。

## 实现注意事项

- **契约兼容**：`AiController`/`AgentController` 的入参 DTO（`ChatRequest`/`AgentQueryRequest`）与出参（`ChatResponse`/`AgentResponse`，含 `references`/`referenceDetails`/`sessionId`/`weatherContext`）保持字段不变；仅替换内部实现。`stream` 端点继续返回 `Flux<String>` SSE。
- **references 提取**：从 `ChatResponse` 元数据 `QuestionAnswerAdvisor.RETRIEVED_DOCUMENTS` 取回检索片段，映射为 `ReferenceDetail`；工具调用结果可用于补充 `weatherContext`。
- **安全**：维持 `SecurityConfig` 对 `/api/ai/**`、`/api/agent/**` 的现有放行/JWT 策略；`knowledge/refresh` 应仅限内部/管理员。
- **日志**：复用 `Slf4j`，记录模型名、耗时、检索条数、工具调用名；不打印用户内容与密钥。
- **向后兼容**：保留 `AliyunAiService.chat/stream` 作为轻量通道，或将其重构为基于 `ChatClient` 的薄封装，避免前端其它调用方断裂。

## 关键代码结构（接口级）

```java
// 工具示例契约（委托现有 Mapper/Client/Service，无新业务逻辑）
public class WeatherTools {
    @Tool(description = "查询指定城市最新实况天气")
    public String getCurrentWeather(@ToolParam("城市名，如 北京") String location) {
        return weatherDataMapper.findFirstByLocationOrderByRecordTimeDesc(location)
                .map(WeatherData::toString).orElse("无数据");
    }
}

// Agent 门面
public interface AiAgentService {
    AgentResponse ask(AgentQueryRequest req);
    Flux<String> streamAsk(AgentQueryRequest req);
    void refreshKnowledge();   // 对接 /agent/knowledge/refresh
}
```
